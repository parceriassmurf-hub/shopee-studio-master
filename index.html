💰 Unit Economics + Cost & Usage

Nova camada obrigatória do projeto: sustentabilidade antes da escala.

Custos a medir

  • Gateway/pagamentos.
  • IA por operação.
  • TTS por narração.
  • CPU/GPU/tempo de processamento.
  • Storage.
  • Banda/egress.
  • APIs externas.

Cenários

  • Usuário leve.
  • Usuário médio.
  • Usuário pesado usando praticamente o limite.
  • Abuso: deve ser bloqueado, não precificado como uso normal.

Regra de decisão

Se o custo do uso máximo razoável não fechar com margem, não fingir que está pronto: otimizar, trocar fornecedor, reduzir limite, mover recurso, ajustar preço ou adiar o recurso.

Não inventar custo: os números reais serão obtidos depois que o pipeline for implementado e medido. A metodologia está fechada; o benchmark real ainda não.

⬇️ Downloader próprio — especificação v1

O que podemos deixar pronto agora para o dia da implementação.

Fluxo oficial

IDLE → VALIDATING → FETCHING → DOWNLOADING → READY Falhas: INVALID_URL UNSUPPORTED_URL VIDEO_NOT_FOUND VIDEO_UNAVAILABLE TIMEOUT FILE_TOO_LARGE VIDEO_TOO_LONG UNSUPPORTED_FORMAT NETWORK_ERROR SECURITY_BLOCK UNKNOWN_ERROR
  • Usuário cola link Shopee.
  • Validar protocolo, domínio e redirects.
  • Obter vídeo elegível.
  • Validar tamanho, duração, formato e resolução.
  • Mostrar preview.
  • “Usar este vídeo” envia para o pipeline.

Limites e consumo

  • Entrada: até 100 MB.
  • Duração: até 60 s.
  • Até 1080p / 30 FPS.
  • Saída principal: 1080×1920.
  • Colar link: 0 crédito.
  • Buscar/preview: 0 crédito.
  • Download com falha: 0 crédito.
  • Produção concluída: -1 vídeo.
  • Retry automático: até 3 tentativas transitórias.

Não tratar remoção de marca d’água como requisito do downloader. O foco é obter e processar o vídeo elegível dentro do fluxo permitido.

Segurança obrigatória

  • Somente HTTP/HTTPS.
  • Allowlist de hosts autorizados.
  • Bloquear localhost, IPs privados e endpoints internos.
  • Revalidar cada redirect.
  • Não aceitar file:// ou esquemas arbitrários.
  • Backend é a autoridade.

Temporários

  • Separar TEMP de resultado final.
  • Arquivos abandonados têm TTL.
  • Limpeza automática.
  • Não duplicar arquivos desnecessariamente.

Observabilidade

  • request_id.
  • user_id.
  • status.
  • tempo.
  • tamanho/duração.
  • erro normalizado.
  • Sem cookies, secrets ou dados sensíveis nos logs.
